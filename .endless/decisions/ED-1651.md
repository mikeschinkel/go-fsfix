A fixture is test code. When a fixture needs knowledge a production package owns (go.mod handling, git operations), go-fsfix imports that package; the production package carries no fixture or other test helper. Test code pulling a dependency is the cheap direction; production code carrying test code is not. Mike stated this in the E-2547 brainstorm on 2026-11-06 when placing GoModFixture, reversing the plan's placement beside the go.mod code. It does not mean go-fsfix integrates every sibling: go-fsfix stays out of go-cfgstore for now because the integration saved no lines.
